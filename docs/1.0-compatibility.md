# Outliner+ 1.0 compatibility

Outliner+ 1.0 replaces the 0.x scene-state model with canonical virtual-layer
paths, explicit state selection and participation, structural inheritance
boundaries, and separate local and effective item properties.

The old model cannot be converted unambiguously. In particular, 0.x used
rendered transparency both as a property and as an implicit state-selection
signal, so an automatic migration could mistake an effective override for a
user's local intent.

For safety, 1.0 uses the `com.ex-asperis.outliner/v1` namespace for virtual-layer
definitions, item assignments, item inheritance, temporary transparency state,
and temporary local-property shadows. Its scene document has schema version 3.
Metadata under the previous `com.ex-asperis.outliner` keys is left untouched and
is never partially applied by 1.0.

When a scene contains a 0.x virtual-layer document but no 1.0 document, the
Outliner displays a compatibility warning and starts with an empty 1.0 model.
Recreate the virtual layers and assignments in 1.0. Ordinary Owlbear item
properties remain authoritative unless a new 1.0 rule is actively overriding
them.

A malformed 1.0 scene-document header or unsupported schema version is rejected
as a whole. The Outliner shows an error and applies no virtual-layer,
inheritance, or participation rules until the invalid scene document is
replaced.

Historical versioned manifests such as `manifest-v0.4.4.json` remain unchanged.
